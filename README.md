# 音频实录质量校验

拖拽式音频质量校验工具。把音频文件或文件夹拖进窗口，逐个音频出一行 CSV。

## 校验项

| 指标 | 要求 |
|---|---|
| 伴奏活动比例 | ≥ 80%（活动时长 / 整歌时长） |
| 人声活动比例 | ≥ 40% |
| 人声相对伴奏平均 RMS 差 | −15 ~ +10 dB |
| 截止频率 | ≥ 15 kHz |
| 码率 | ≥ 320 kbps |
| 底噪 | < −40 dBFS |
| RT60 | < 0.3 秒 |

阈值都在 `src/analysis.rs` 顶部，CSV 表头在同文件的 `COLUMNS`。

## 下载

去 [Releases](../../releases) 拿对应平台的包，或者在 Actions 里下最新构建产物。

- **macOS**：`AudioQC-macOS.zip`，解压得到 `AudioQC.app`（通用二进制，Intel 和 M 系列都能跑）。
  首次打开提示"无法验证开发者"是正常的（未签名），右键点图标选**打开**即可，
  或终端执行 `xattr -dr com.apple.quarantine AudioQC.app`。
- **Windows**：`AudioQC.exe`，单文件直接双击。
- **Linux**：`AudioQC-linux`，`chmod +x` 后运行。

## 自己编译

```bash
cargo build --release       # 产物 target/release/audio_qc
cargo test --release        # 6 项算法自检
cargo run --release -- /path/to/音频目录    # 也可以直接传路径
```

依赖全是纯 Rust（symphonia 解码、rustfft 频谱、egui 界面），
**不需要 ffmpeg**，不需要任何系统运行时。

## 几个指标的说明

- **底噪**取整段音频静音部分的能量平均（静音段 = 活动门限以下、且高于 −90 dBFS 的帧，
  −90 以下是剪辑挖的绝对零，不是本底噪声）。静音总时长不足 0.5 秒就不报数，
  因为连续演奏的轨根本没有静音可测，硬报出来的只会是"最安静的乐句"。
- **RT60** 没有冲激响应可用，是从乐句衰减段用 T20 外推的估计值，只保留
  拟合优度 R² > 0.9、时长合理、且整段在底噪之上的衰减段。衰减段少于 10 段时
  会在结论里标"建议人工复核"——证据太薄，不该单凭它退货。
- **截止频率**找 8 kHz 以上的"砖墙"跌落点取半功率点；没有砖墙就按满带宽算。
  偏保守，只会低报不会高报。
- **码率**按 文件字节数 / 时长 实测，VBR 拿到的是真实平均码率。
